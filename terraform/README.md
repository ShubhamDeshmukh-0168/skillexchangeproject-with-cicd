# Infrastructure — Terraform (fully automated)

This creates everything the app needs from a blank AWS account: a private
VPC, public subnet for the app server, private subnet for RDS (never
internet-reachable), the EC2 instance itself (bootstrapped with Java,
Tomcat 10.1, Nginx, and the DB schema already loaded), and the RDS MySQL
instance.

This is now part of the single `.github/workflows/full-deploy.yml`
workflow — see `CICD_SETUP.md` in the repo root for the full setup guide
and the exact secrets needed. This file covers infra-specific details only:
what gets created, how to run it locally, and teardown.

---

## One-time manual setup this still needs

Only AWS credentials for GitHub Actions — an IAM user (or OIDC role) with
permission to create S3/VPC/EC2/RDS/IAM resources. The Terraform state
bucket itself is created automatically on first run.

Full secret list and exact steps: see `CICD_SETUP.md` in the repo root.

---

## What gets created

| Resource | Notes |
|---|---|
| VPC + 2 public + 2 private subnets | across 2 AZs |
| Internet Gateway + NAT Gateway | private subnet gets outbound internet, no inbound |
| EC2 (`t3.micro`, Amazon Linux 2023) | in a **public** subnet, Elastic IP, bootstrapped via `user_data` with Java 17, Tomcat 10.1, Nginx reverse proxy on :80, DB schema pre-loaded, `/opt/deploy.sh` for future SSM-triggered deploys |
| RDS MySQL 8.0 (`db.t3.micro`) | in **private** subnets only, security group only allows 3306 from the app server, password generated by `random_password.db` |
| IAM role + instance profile | SSM access for both Session Manager (interactive) and Run Command (what the pipeline uses to deploy) — no SSH key pair exists anywhere in this setup |

Change instance sizes, region, or CIDR ranges in `terraform/variables.tf`.

## Running it locally instead (optional)

```bash
cd terraform
cp terraform.tfvars.example terraform.tfvars   # optional overrides, don't commit it
terraform init \
  -backend-config="bucket=tfstate-skillexchange-<your-account-id>" \
  -backend-config="key=skillexchange/terraform.tfstate" \
  -backend-config="region=us-east-1"
terraform plan
terraform apply
```
(The bucket must already exist for a local run — the GitHub workflow
creates it automatically on its first run; locally, create it yourself
first with `aws s3api create-bucket --bucket tfstate-skillexchange-<your-account-id>`.)

---

## Tearing it down

```bash
cd terraform
terraform destroy
```
Or trigger a `workflow_dispatch` run of a destroy job if you add one —
not included by default so a stray click can't delete production.

## Security notes

- RDS is **never** publicly accessible — `publicly_accessible = false`,
  private subnets, security group only trusts the app tier's SG.
- No SSH key pair exists and port 22 is never opened — all access
  (deploys and interactive debugging) goes through AWS Systems Manager,
  authenticated via the instance's IAM role rather than a key you'd have
  to generate, store, and rotate.
- The DB password is generated by Terraform (`random_password.db` in
  `rds.tf`) and never appears in this repo, in GitHub, or in any log — it
  flows straight from Terraform state into the instance's systemd
  service. It does live in Terraform state in plaintext (normal for
  Terraform), so keep the state bucket private — it already is, via the
  public-access-block the workflow sets when creating it.
- `terraform.tfvars` and `*.tfstate` are git-ignored regardless, as a
  second line of defense.
